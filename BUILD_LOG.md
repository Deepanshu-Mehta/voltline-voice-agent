# Build log

Three lines a day: what changed, what the numbers were, what broke. This becomes the video's engineering-decisions script.

## 2026-11-12 (Phase 1)

- **Changed:** content (14 products, policies, 6 guides, 29 FAQs, 20 demo orders), hybrid retrieval, 5 tools + knowledge-base search tool, streaming `/chat` brain, 60-question eval, Next.js site.
- **Numbers:** retrieval hit@3 100% on 47 scored questions; retrieval about 3 ms per query in process (BM25 + local bge-small, 46 chunks); 33 unit tests pass. No LLM score yet: no API key configured.
- **Decisions:** local embeddings instead of a vector database (no network hop, works offline); retrieval before the LLM rather than as a tool (saves a round trip on fact questions); order dates stored as offsets so the demo never goes stale; ticket and callback numbers start at 20001 and 1001 so they never sound like four-digit order numbers.
- **Frontend polish:** line drawings for all 14 products, an Ask Volt drawer on every page (the conversation persists while browsing), product filters and sorting, FAQ accordion, docs sidebar, mobile menu, 404 page. Fixed a client bundle importing `node:fs` by moving formatting helpers to `web/lib/format.ts`.

## 2026-11-12 (Phase 2)

- **Changed:** `/voice` WebSocket pipeline (Deepgram Nova-3 -> agent brain -> Cartesia Sonic 3.6), browser capture worklet + Silero VAD barge-in + gapless player, server-side Silero VAD turn-taking with early Finalize, unfinished-sentence grace, tool fillers, LLM fallback provider, per-turn timings, live latency table, audio test set (90 clips + 17 scenario clips), audio eval, Playwright browser driver. Groq is now the default LLM (user's choice).
- **Numbers:** text eval 81.7% correct, 0% hallucination, 10/10 out of scope, 100% retrieval hit@3 (gpt-oss-20b). Voice, clean clips on gpt-oss-120b: WER 0.00, end of turn 714 ms (was 1,378), LLM first token 618 ms, TTS first byte 118 ms, server response 1,493 ms median. Browser driver: 8/8 scenarios pass; barge-in stopped audio 191 ms after the user started; measured response about 2.2-2.6 s, mostly on the DeepSeek fallback (LLM first token about 1.1 s).
- **Broke / learned:** Groq free tier allows 8,000 tokens a minute and 200,000 a day per model, which voice traffic exceeds within minutes; Gemini 2.5 Flash is closed to new users and newer Flash models returned 503. Deepgram adds about 500 ms after its endpointing and about 400 ms to answer Finalize, so Finalize is now sent early. Deepgram writes "PulseBuds" without keyterms; Cartesia reads 4512 as "forty-five twelve", so clips speak order numbers digit by digit. Judge rubric was too strict for short spoken answers (9 of 11 failures); rubric fixed, re-run pending the rate limit.

## 2026-11-12 (Phase 2 hardening: real microphone, Gemini)

- **Changed:** Gemini (`gemini-3.5-flash-lite`, reasoning "minimal", paid key) is the default LLM, DeepSeek the fallback. Fixes found by a real-microphone session and by re-running every test on Gemini: tool calls now send Gemini's thought signature back (every tool turn was failing with HTTP 400 and silently using the fallback); a reply that is fully generated but still playing can be interrupted, and the history keeps only the heard words; a turn is no longer ended when the final transcript stops mid-sentence ("...Headphones in" / "stock?"); a stale VAD time no longer makes a one-word turn ("Okay.") look 28.8 s slow; a rate-limited main model is skipped for the time the provider asks (max 5 min); a provider that is out of credits gives a plain error and closes the socket. Product fact cards no longer carry the restock date (the model used it to skip `check_stock`); model numbers are spoken only on request. The text eval records fallbacks per question; partial runs no longer overwrite `latest.json` / `audio-latest.json`.
- **Numbers:** 52 unit tests. Text eval (60 questions, all answered by Gemini, 0 fallbacks): 98.3% correct (was 81.7%), 0% hallucination, tool choice and arguments 100%, 10/10 out of scope, first token 1,038 ms median. Browser driver: 8/8; response measured from the audio 2,543 ms median, 3,772 ms p95. Audio eval, 90 clips, 0 errors: WER 4.1% clean / 8.1% cafe noise / 11.2% telephone; key-term accuracy 87.5% / 75% / 75%; end of turn 719 ms, LLM first token 1,261 ms, TTS first byte 101 ms, server response 2,181 ms median (clean). Real microphone, 6 turns: end of turn 706-721 ms, TTS first byte 75-332 ms.
- **Broke / learned:** the cascade is 0.7 s over the 1.5 s target and the LLM's first token is most of it (Groq was 0.6 s but its free tier lasts minutes). Open issues from the audio eval: (1) "order 9999" is transcribed "9900 and 99" in all three conditions; (2) 3 of 60 noisy/phone clips were split mid-sentence, and the eval then records only the tail as the transcript; (3) WER counts "cancelling/canceling" and "20K/20 k" as errors, so the scorer needs spelling and number normalisation. The Cartesia free credits ran out mid-eval (HTTP 402). Server-side barge-in now stays armed for the whole playback, so echo on loudspeakers needs a real-microphone check.

## 2026-11-13 (Phase 3: speech-to-speech, system B)

- **Changed:** project retargeted to an evaluation of cascade (A) against speech-to-speech (B); phone, LiveKit and Vapi dropped. System B: `server/app/voice/s2s.py` bridges `/voice` (`mode: "s2s"`) to Gemini Live (`gemini-3.1-flash-live-preview`) with the same prompt file and tool registry plus `search_knowledge_base`, the same wire protocol, and the same turns table (`mode = "s2s"`). Cascade / Speech-to-speech switch on the Talk page; the browser driver clicks it (`--mode`). Speech-to-text now reconnects when the Deepgram stream dies mid-call. Driver checks accept "24 month" and "two point four". Issue log started in `qa/issue-log.csv` (10 issues).
- **Numbers:** model trial on 4 clips: 3.1 Flash Live 4/4 correct, first audio 1.7-2.5 s; 2.5 native audio 2/4 (invented tool argument names), 3.2-7.1 s. Browser scenarios, same build: B 6/8 (then 7/8 after the scorer fix), response from the audio 1,953 ms median; A 6/8 (8/8 after the fixes), 2,344 ms median. B cuts the user off at a 1.5 s mid-sentence pause in 4 of 4 runs. 55 unit tests.
- **Broke / learned:** the google-genai SDK defaults to API v1, which has no Live endpoint (HTTP 404); v1beta works. B calls a tool even for prices, which A answers from retrieval. A Deepgram "keepalive ping timeout" left a call deaf for the rest of the session (1 of 4 runs of S6); found by the driver, root-caused from the server log. B's own transcript of its speech is not reliable ("2 4 gigahertz"), so Phase 5 transcribes the recorded audio instead.
